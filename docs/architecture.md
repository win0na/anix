# Architecture

anix is one flake with two host configurations. The WSL host is the development
system and the NFS server. The Mac is the Darwin builder and the media machine.
Both hosts read the same home configuration and the same project tree.

## Topology

```text
Windows 11
  anix (Tailscale node on Windows)
  WSL2, mirrored networking
    anix (NixOS-WSL, x86_64-linux)
      ~/src  ------------ NFSv4.1 ----------->  amac (macOS 26, x86_64-darwin)
      nix-daemon  <------ ssh-ng build -------  /Users/winona/src
                                                  nix-daemon
```

The Mac runs nix-darwin on top of macOS. The WSL host is not a Tailscale node;
it uses the Windows node through mirrored networking. The Windows node and the
WSL host share the name `anix`; from the Mac the name resolves to Windows, and
from WSL it resolves locally. The WSL host reaches the Mac at `amac` through
MagicDNS. [Networking](networking.md) covers the address asymmetry.

## Flake inputs

| Input | Source | Used by |
| --- | --- | --- |
| `nixpkgs` | `nixos-unstable` | anix |
| `nixpkgs-2605` | `nixos-26.05` | amac |
| `nixos-wsl` | `main`, follows `nixpkgs` | anix |
| `nix-darwin` | `nix-darwin-26.05`, follows `nixpkgs-2605` | amac |
| `home-manager` | `master`, follows `nixpkgs` | anix |
| `home-manager-2605` | `release-26.05`, follows `nixpkgs-2605` | amac |
| `sops-nix` | follows `nixpkgs` | anix |
| `sops-nix-2605` | follows `nixpkgs-2605` | amac |
| `nix-homebrew` | follows `nixpkgs-2605` | amac |
| `herdr-src` | `kitknox/herdr` tag `rootshell-v0.1.10`, `flake = false` | both |

nixpkgs 26.05 is the last release that builds and supports x86_64-darwin.
nixos-unstable is the current channel for the WSL host. Home Manager and
nix-darwin stay on the same channel as their nixpkgs input, and the shared home
modules use only options present in both branches.

The two `sops-nix` inputs are intentional. Each host follows its own nixpkgs
channel, so the sops package and module evaluate against the same package set
as the host.

## Module graph

```text
hosts/anix  ->  modules/common  ->  modules/nixos   ->  home-manager
hosts/amac  ->  modules/common  ->  modules/darwin  ->  home-manager

home/winona/default  ->  shared home configuration
home/winona/anix     ->  /home/winona
home/winona/amac     ->  /Users/winona
```

Both hosts enable Home Manager integration with `useGlobalPkgs = true` and
`useUserPackages = true`. `modules/common` holds only options that exist on
both platforms. A platform-specific module belongs in `modules/nixos` or
`modules/darwin`, never in `modules/common`.

## Configuration and state

The repository is the source of truth. On the WSL host the checkout lives at
`~/src/anix`. On the Mac it builds from `~/.config/anix`. The WSL checkout is
visible through the export at `/Users/winona/src/anix`, but the Mac does not
build from that copy. A local clone keeps `darwin-rebuild` working when the NFS
mount is down, avoids Git `dubious ownership` across the NFS uid mapping, and
prevents a broken switch from removing the source it is building from.

`~/src` holds projects, not configuration. The Mac mounts the WSL export at
`/Users/winona/src`, so both hosts see the same files at the same relative
path. Build artifacts such as `target/`, `DerivedData`, and `node_modules`
stay on local disk.

Secrets live encrypted in `secrets/`. The age private key lives outside the
repository at `~/.config/sops/age/keys.txt` on each host. Herdr and OpenCode
configuration is generated by Home Manager; their state stays in the XDG state
and config directories.

## Boot and build flow

1. Windows boots, a logon task starts the WSL distro, and Tailscale starts.
2. anix starts `nfsd`, exports `~/src`, and runs `nix-daemon`.
3. The Mac auto-logs in, Tailscale starts, and a LaunchDaemon waits for the
   network before mounting `anix:/` at `/Users/winona/src`.
4. `scripts/rebuild anix` runs `nixos-rebuild switch` on the WSL host.
5. `scripts/rebuild amac` runs `darwin-rebuild switch` on the Mac, either
   locally or over SSH from WSL.
6. Darwin derivations can run on the Mac through `nix.buildMachines`, while the
   WSL host keeps the Linux build cache.

## Boundaries

- The Mac never builds from the NFS copy of the config repository.
- Projects live on NFS; build artifacts do not.
- Secrets are encrypted at rest; no plaintext key enters the repository.
- Herdr core changes stay small and patch-based. Behavior lives in plugins.
- The Mac is a build appliance. Its desktop is minimal by design.

## Limitations

- x86_64-darwin support ends with nixpkgs 26.05 on 2026-12-31.
- The first `darwin-rebuild` over SSH can hit the macOS App Management prompt.
- NFS file watching from the Mac side is unreliable. Local builds are the fix.
- Tailscale with WSL mirrored networking has open regressions in 2026.
